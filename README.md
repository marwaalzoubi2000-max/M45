# مصعب • رياضيات — Android 2.0

تطبيق مستقل لتشغيل أوزان MUSAB V12.2 على الهاتف. لا يغيّر تدريب Kaggle ولا يتصل بخادم، ولا يتضمن بيانات أو أوزان المستخدم.

## الاستخدام المباشر

1. نزّل `best.pt` من Output جلسة التدريب إلى الهاتف. يدعم أيضًا `laptop_fp16.pt`.
2. افتح التطبيق واضغط **تحميل best.pt من الهاتف** واختر الملف نفسه.
3. انتظر اكتمال نسبة التحميل، ثم اكتب المسألة واضغط **حل**.

**لا تحتاج تحويلًا أو نوتبوك إضافيًا.** الدعم خاص بصيغة ومعمارية V12.2 ذات 36,321,280 معاملًا؛ ليس قارئًا لأي نموذج PyTorch. لا تستخدم `resume.pt` لأنه يحتوي حالة التدريب. ملفات ONNX من الإصدار السابق ما زالت مدعومة.

## التحسينات

- تحميل مباشر لـ FP32 وFP16، مع فحص أسماء وأشكال الأوزان والملفات الناقصة والقيم غير المنتهية.
- تحميل تدريجي مع نسبة تقدّم، وحفظ النموذج بعد إغلاق التطبيق.
- ظهور الجواب أثناء التوليد وزر إيقاف؛ زمن الحل ظاهر عند اكتماله.
- نسخ ومشاركة الجواب، وسجل محلي لآخر 20 مسألة مع مسحه.
- إعادة تعيين مع تأكيد؛ تحذف نسخة التطبيق والسجل فقط، ولا تمس ملف الهاتف الأصلي.
- استبدال ذري للملف بعد نجاح الاختبار، مع إبقاء النموذج السابق إذا فشل تحميل البديل.

## كيف يعمل الدعم المباشر؟

التطبيق يقرأ ZIP وبيانات tensor من ملف `torch.save` باستخدام قارئ Java محدود لبروتوكولي pickle 2 و4. لا يشغّل Python ولا ينفذ دوال pickle. أسماء العمليات والأنواع المسموحة محددة، ويُرفض ما عداها. يربط المصفوفات بمعمارية ONNX مضمّنة **دون أوزان**، ثم يشغّل ONNX Runtime محليًا. تحويل الملف على Kaggle لم يعد مطلوبًا.

أداة `build_pt_template.py` تعمل أثناء بناء التطبيق فقط، وتُنشئ الرسم وملف ربط أسماء الأوزان في assets. لا تُضمّن أوزان عشوائية أو مدرّبة داخل التطبيق.

## APK والبناء

من Actions افتح تشغيلًا ناجحًا لـ **Build Android APK** ثم نزّل **MusabMath-debug-APK** وفك الضغط وثبّت APK. هذه نسخة اختبار وليست إصدار Google Play. Android 8+، arm64-v8a أو x86_64.

لبناء المشروع: JDK 17 وAndroid SDK 35 وGradle 8.11.1، ثم:

```bash
pip install -r tools/requirements.txt
python tools/build_pt_template.py
gradle testDebugUnitTest lintDebug assembleDebug
```

## الاختبارات والحدود

CI يولّد ملفات `.pt` فعلية بنفس طريقة `torch.save`، بصيغ FP32/FP16 وبروتوكولي 2/4، ويحملها بواسطة نفس كود Java المستخدم في التطبيق، ثم يقارن logits مع PyTorch عبر أربعة أطوال سياق. يشمل OrderedDict، الإيقاف، ورفض ملف ناقص أو بأشكال خاطئة أو NaN أو نوع غير مدعوم. هذه مقارنة تنفيذ، وليست قياسًا لدقة النموذج المدرّب.

لم يُقَس زمن الاستجابة أو الذاكرة على هاتف المستخدم بعد. التوليد ما زال يعيد حساب السياق لكل رمز (دون KV cache)، وقد يكون بطيئًا. الإيقاف ينتظر اكتمال عملية الرمز الحالية. FP16 يُقرأ إلى FP32 في الذاكرة لدعم CPU. حد الملف 300 MiB؛ قد يحتاج استبدال نموذجين ذاكرة إضافية مؤقتة.

اكتب الأسئلة بالإنجليزية أو الرموز لأن بيانات التدريب إنجليزية؛ الواجهة عربية. حد السؤال 192 رمز بايت شامل القالب، والجواب 64 رمزًا. دقة الأجوبة تعتمد على الأوزان المستوردة. لا توجد آلة حاسبة بديلة تعطي نتائج مزعومة باسم النموذج.

المراجع: [PyTorch serialization](https://docs.pytorch.org/docs/stable/notes/serialization.html)، [ONNX Runtime Java](https://onnxruntime.ai/docs/get-started/with-java.html).
